# 0.5.0 · AI 个股分析

此前的研究模块只计算本地指标，并提供手工笔记。现在新增真正的大模型调用链路，个股页的“AI 分析”以自动生成的报告为主，个人备注与本地指标折叠保留。

## 使用

1. 设置 → AI 模型，启用并填写接口基础地址、模型 ID、API Key，保存。接口采用兼容 Chat Completions 的协议，支持 DeepSeek、通义等兼容服务；模型 ID 以服务商控制台为准。填写 `/v1` 等服务商要求的基础路径，程序会追加 `/chat/completions`；也接受完整端点。
2. 确认本地已有该股行情、历史、F10、资金和公告；缺少的资料可从对应子页更新。Tushare 提供市场资料，模型接口负责解读，两者配置独立。
3. 个股 → AI 分析，选择盘中短线、日线波段或基本面长线，点击“生成 / 更新 AI 分析”。
4. 阅读结论、技术走势、资金观察、公司与财务、公告事件、情景与观察条件、风险与反证、数据缺口。通过 E1…E10 引用展开生成时的数据依据。

## 行为与边界

- 在独立线程执行模型请求，行情、星图、资料同步与界面继续运行。全库同时最多一个模型请求；相同数据、口径、模型与提示版本复用最新成功结果或进行中的请求。页面刷新不触发付费模型调用。
- SQLite schema 11 新增报告归档，保留完整公开输入快照、模型/接口、生成时间、结构化报告、错误与最近20条展示历史。已有个人笔记保持原样，不发送给模型。
- 本地数据变化或模型切换后，已有报告继续标明旧快照，并提示按需更新，不自动把旧报告标为最新。
- 只发送当前股票的公开报价、计算指标、最近40根日线、最多60条分钟、公司、财务、估值、股东、20条资金及10条公告摘要。不是联网检索，不读取公告链接正文，不发送个人备注、组合持仓、Tushare Token 或模型配置。
- 模型输出必须包含七个章节及有效输入引用；空输出、截断、格式错误、虚构引用不标为成功。HTTP错误、超时和额度问题显示明确状态，不自动重试产生额外费用；进程中断的请求在四分钟后可重试。
- 引用验证仅确认编号存在，不能自动证明模型的数字、推理或结论正确。数据不足、历史/延迟和复权限制在输入及页面中保留；输出不等同交易指令。当前不支持 AI 历史时点回放。
- API Key 可在软件内保存于本机配置，或使用 `GETRICH_AI_API_KEY` 环境变量（优先）。设置读取、诊断及错误不返回密钥；非本机接口要求 HTTPS，禁止带凭据的 URL 和重定向。备份配置文件时须按凭据文件保管。

## 接口

`settings.save` 增加 `ai: {enabled, base_url, model, api_key?, timeout_seconds?}`，留空输入框时前端不提交 api_key；显式空字符串清除本地密钥。`settings.get.ai` 仅返回非敏感配置与凭据是否存在。

`ai.analysis.generate` 接收 `symbol, market, mode, basis, factor_source`，立即返回 `{id, reused}`。`ai.analysis.get` 按股票、研究方式与口径读取结果，后台完成后 status 从 running 变为 succeeded 或 failed。报告与个人备注独立存储。

协议参考：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Ollama 兼容接口](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)。这些是接口协议依据，不代表所有模型的输出质量或服务权限已验证。

本版自动测试使用隔离的本机模拟模型，覆盖实际 HTTP 请求、异步状态、落盘与重开、复用、隐私边界、格式错误和鉴权失败。未持有用户的模型凭据，真实服务的鉴权、费用与报告质量须完成配置后验证。
