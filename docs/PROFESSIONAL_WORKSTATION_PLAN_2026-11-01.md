“工程模块已落地”不表示所有外部数据已取得：

- 当前配置为Tushare，未配置的第二实时源、逐笔/盘口源不能凭空提供。已实现独立授权报价CSV和来源核对；接入额外API须提供其授权及契约。
- 专业数据同步分别报告接口权限和错误。供应商分红原始证据不冒充个人净分红，涨跌停价不冒充完整停牌/公司行为认证。
- 严格时点回测需来源档案；没有历史known_at时使用真实本地观测时钟，不能将今天导入时间回写成过去。算法冻结首个可得日线版本，未实现全市场动态池/多证券撮合，不声称消除全市场幸存者偏差。
- 财务研究按公告日过滤，并保留修订及获取记录；缺认证时点档案时，不能保证所见值就是当年首次披露值。当前均线回测不使用财务因子。
- 截至2026-11-01为非交易日，模拟时钟/压力/断流回归与真实盘中连续验收分别陈述。下一交易日仍需观察已授权实时接口的实际返回。

### 设计基线归档（0.3.0—0.3.1）

## 产品目标与默认研究方式

目标是形成个人可持续使用的研究系统：知道数据是否可信，形成可核对的分析，保存研究依据，并在后续复盘。用户已确认盘中短线、日线波段、基本面长线“都需要”，三种方式均纳入产品范围并实现独立工作区。沪深京 A 股共享分钟、历史、财务估值和研究数据；已导入港美股支持本地日线分析，当前分钟及财务资料源仍限定 A 股。

整个产品划分为行情观察、个股研究、条件选股、研究记录、组合复盘和数据运维六个工作区。数值计算统一由 Rust 核心提供，桌面与浏览器复用；不在前端维护两套指标公式。

## 0.3.1 三种研究方式的交付与验收

| 工作区 | 已实现分析 | 独立记录模板 | 后续扩展 |
| --- | --- | --- | --- |
| 盘中短线 | 最新分钟收盘、样本成交均价及偏离、连续15交易分钟收益、样本高低与量额；过滤未来/无效时钟、报告缺口和时效 | 盘中结构、失效与流动性、观察价位与纪律、执行复盘 | 逐笔/盘口授权接入、异动与事件预警、成交执行复盘 |
| 日线波段 | 收益、均线、RSI/MACD/ATR、波动、回撤、相对均量；复用历史增量落盘 | 趋势证据、波段失效、观察区间、波段复盘 | 复权、指标副图、指数相对强弱、多股比较、命名策略 |
| 基本面长线 | TTM估值与股息率、ROE、增长、利润率、负债、现金收益比；排除截止日前未披露财报 | 商业逻辑、财务反证、估值假设与跟踪、财报假设复核 | 行业横比、财报修订版本、估值情景模型、公告事件轴 |

三种工作区共用 Rust 分析服务，桌面/Web 均可切换，记住最近选择。股票与研究方式共同决定草稿、保存版本和历史记录的归属；旧 schema 8 记录迁入波段工作区。每种方式有独立的版本冲突检查，保存时同时固定其数据时钟、来源与分析证据。快速切换时，旧请求不能覆盖当前方式；未保存草稿不会被后台刷新冲掉。

数据更新复用有界后台任务和已有缓存/退避机制：短线对应分钟任务，波段对应历史任务，长线对应 F10 任务；活跃研究页每30秒检查缓存，满足刷新条件才提交，正在执行的任务合并。手动“更新研究数据”走相同任务通道；“重算本地分析”只计算本地数据。接口无权限或失败时保留已有数据并显示来源状态，不将延迟日线伪装为分时。

短线均价明确为样本成交额/成交量，缺少的分钟不补日线，午休不计为交易分钟；15分钟收益要求16个连续交易分钟样本。长线记录分别显示报告期、公告日、估值日与获取时间；缺少公告日的财报不纳入截止日分析。现有缓存可能被后续修订，尚不能声称具备完整点时数据库或无前视偏差回测能力。

验收覆盖分钟未来值/缺口/时间坐标、财报公告日过滤、三种笔记独立保存与重启、schema 8迁移、快速切换和迟到返回、后台任务合并及三档窗口布局。此处完成三种方式的基础研究流程，不把后续盘口、组合或回测模块列为已完成。

## 0.3.0 已开发的研究闭环

进入“行情 → 选择股票 → 研究分析”。先核对日期、样本量、来源与价格口径，再查看指标。资料不足显示空值，不以零代替；本轮使用原始价格，界面持续提示未复权影响，不能把跨除权收益直接解释为投资收益。

条件选股以本地最新可用交易日期为统一截面，限定 A 股人民币报价，排除未来时间、无日期和无报价记录；按成交额降序，最多展示100个候选，同时报告匹配、可用及排除数量。自定义阈值和两组快捷条件在两端均可用。候选结果支持打开个股继续研究，结果不会自动执行交易。

研究记录按股票分开：研究假设与证据、风险与反证、观察条件与计划、复盘。草稿留在当前会话；保存才写入数据库。每次保存新增版本，并保存当时计算的分析日期、数据批次、样本量、指标、来源及价格口径。后续数据修订不会改写既有证据。版本号校验阻止旧窗口覆盖新内容；冲突保留草稿并提示核对，切股或后台读取不会将另一只股票的内容写入当前记录。

“设置 → 存储与诊断”支持创建后台数据库备份，路径在数据目录的 backups 内。采用 SQLite `VACUUM INTO` 一致快照，完整性检查及刷盘成功后才将 `.partial` 文件改为 `.db`；源数据库不被覆盖。配置文件不包含在数据库备份中，请单独保管。恢复时关闭程序、保留原库，将备份复制为目标数据库，先用对应版本打开验证。

## 后续交付分组与验收

### A：先完善可信数据与研究效率

1. 数据源能力、权限和新鲜度按数据集显示；对最新成功、失败、退避与报价源时间分别建模。实时行情需供应商授权，不能由缓存或刷新频率替代。
2. 建立公司行为与复权因子版本；同一日期的原始价、前复权、后复权可追溯，均线和收益口径随切换一致；拆分/分红基准样本与独立计算对照。
3. 数据质量报告覆盖单位、时区、交易日、重复、负量额、缺口及跨源偏差。错误不混入排名；修订只补变化区间，不能继续把历史全部视为永不修订。
4. 命名选股规则、研究池和标签持久化，导出包含规则、日期与覆盖范围。关键流程不依赖临时终端或 API 调用。

验收：固定样本逐项核对；重启保留配置与规则；开盘、午休、收盘转换在真实交易时段观察；断网恢复保留上一有效画面，数据变化可追溯。权限与供应商服务可用性属于外部前置条件。

### B：完善多维研究与组合复盘

1. F10 增加同行估值、盈利质量、现金流、负债和披露时间对照；历史研究只使用当时已披露资料。
2. 日线与分时增加指标副图、相对指数强弱及多股同期比较；不同币种和复权口径不直接合并。
3. 增加价格、量能及公告事件预警；按规则版本和触发窗口去重，展示来源、条件、触发时间及恢复状态。
4. 组合导入真实成交与现金流后计算成本、已实现/未实现收益、回撤、行业集中度与持仓贡献；分红、送股、费用按实际记录处理。

验收：组合余额与导入记录逐笔对账；预警不重复轰炸、不以历史报价触发“实时”事件；恢复备份后组合和研究版本一致。

### C：建设可信的策略验证

先补点时数据、退市/停牌样本、交易日历、公司行为和可执行价格，再建设回测。显式处理交易限制、成交量约束、手续费、税费、滑点和缺失数据；参数与数据版本固定保存，区分训练与验证区间。报告基准超额、回撤、换手、交易明细及成本敏感性，不能只展示一条收益曲线。

验收：相同输入可复现；无未来函数；停牌与无法成交情形可解释；样本外结果与成本扰动均可审查。在这些条件具备前，本轮指标和选股结果只作为研究事实与条件匹配，不声称策略有效。

## 工程约束

保留 SQLite WAL 与本地优先设计，不为个人工作台无必要引入额外数据库服务。供应商网络、历史计算及用户操作继续与报价快速通道分离；后台任务有界、可诊断。新增模块通过 invoke 契约接入，桌面与 Web 共用逻辑。数据库迁移、旧版本笔记、时间截止、并发冲突、缓存失效、备份恢复和大小窗口布局均进入回归。发布包不含 Token、个人笔记或数据库，根目录运行文件不自动覆盖。

## 计算口径与来源

RSI 使用 Wilder14 平滑，完全无涨跌时取中性50；ATR使用14个真实波幅；EMA以对应周期SMA为种子，MACD为12/26/9，柱为2×(DIF−DEA)。20日波动使用20个对数收益的样本标准差并按252日年化；60根回撤按收盘路径峰值计算；量比使用最新一根成交量除以前20根均量，与交易所实时量比不同。历史不足不补值，未复权限制在页面显示。

参考：[TA-Lib RSI 文档](https://ta-lib.github.io/ta-doc/indicator/RSI.htm)、[SQLite 一致性备份说明](https://www.sqlite.org/lang_vacuum.html)、[Tushare 实时日线权限及接口](https://tushare.pro/document/1?doc_id=372)。供应商权限及运行限制以实际返回和配置为准。
