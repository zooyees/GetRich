# 0.2.11 · 本地数据库与增量下载

当前运行实例 0.2.10 的只读诊断显示，自动采集已启用、状态为 outside_session、无当前错误。2026-10-31 是周六，非交易时段不请求实时行情；页面定时读取本地数据库不代表供应商产生新报价。新版在星图底栏明确显示该原因。此前运行的权限错误不代表本次账号状态，盘中以实际接口结果为准。

同时检查了用户本地日志：2026-10-28 上海时间 14:38、14:48、14:58、15:09 均记录了供应商明确返回“没有接口(rt_k)访问权限”。这直接解释了这些盘中轮次未产生新行情；当前进程没有错误并不能证明实时权限已开通。缓存和数据库不能解决账号授权问题，应在权限具备后的交易时段验证真实成功时间持续推进。

SQLite 升级至 schema 7，新增成功响应缓存、按日期的历史原始记录和已同步区间。成功数据自动事务落盘，重新启动后继续使用；按账号指纹、接口、服务地址、参数和字段隔离，不保存 Token。失败响应不标记完成。

日线和指数历史、个股日估值、日资金数据按缺失日期区间下载；合并重叠区间，不用最早/最晚日期掩盖中间缺口。已有本地日线直接复用；旧版完整历史记录在数量匹配后可作为连续区间凭据。没有完整性凭据的文件导入只认可实际存在的日期，需要检查其间缺口。历史任务返回本地与新增记录的完整合并结果，周/月线继续基于完整日线生成。

最新实时 rt_k、rt_min_daily 永不进入历史缓存。当日数据保持可更新；历史非空响应长期复用，空响应短暂缓存以免永久遗漏延迟发布的数据。公司、财务、股东资料按一天更新，公告等可变资料按短期缓存检查新版本；这些会变更的内容不能永久冻结。原始记录和完成区间原子提交，网络故障保留已成功下载的区间。

设置页“存储与诊断”显示数据库路径及缓存响应、历史记录、同步区间数量。旧库启动自动增量迁移；升级前备份数据库，降级需恢复 schema 6 的备份。程序不会删除旧行情，也不重新创建用户数据库。本轮开发测试使用隔离数据库，未迁移正在运行的用户数据库。

回归包含：持久化后关闭模拟服务器并重建客户端仍能读取；区间扩大只请求新日期；已有文件导入日线零网络复用；缺口与重叠区间运算；实时接口绕过缓存。供应商夹具使用本机端口，不消耗实际账号额度。非交易时段测试不能代替盘中观察。

近期非空响应也可能尚未发布最后一天的数据，因此仅将实际返回到的日期标记完成，避免永久漏掉尚未发布的尾部。新增对此情形的回归。全量 145 项 Rust、40 项 Web 回归及严格 Clippy 检查通过。
