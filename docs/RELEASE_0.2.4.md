# GetRich 0.2.4 · 数据源限流与盘中星图修正

- 按账号与接口分别计算请求额度和冷却；继续使用 SQLite 共享预算，多个进程不会各自重复获得一份额度。分钟接口限流不会封锁 `rt_k`、日线、市值和财务接口。识别小时／天频次，遵守服务端冷却时间；权限不足只暂停对应接口 10 分钟，避免无意义重试。
- 全市场后台轮询按交易所合并为 3 个请求，替代默认 7 次分散请求；自选仍分批请求。根据批次数和 `rt_k` 配额调整有效间隔，并留出 20% 额度供手动读取。50 次／分钟时，3 批的最短间隔为 4,500 毫秒；原配置 5,000 毫秒不变，1,000 毫秒自动放慢，避免软件主动超额。
- 星图手动刷新在有效交易时段、日历确认当日开市后优先获取全 A 股实时快照；后台仅看自选不会缩小手动星图范围。实时接口不可用时，明确报告原因及收盘行情回退，任务保留部分成功状态。任何交易所批次失败或触及单批上限时，不提交不完整的实时批次，已有行情继续保留。
- 不再为缺少源时间的 `rt_k` 数据填入当前时间，防止旧数据被标为新行情。星图区分实时快照、收盘行情、混合来源和历史截面。
- 桌面和 Web 筛选新增市值日期策略：默认使用最近有效收盘市值（最多落后 7 个自然日），也可选择严格同日市值。未来日期、无日期和超期市值始终排除。报价日期、权重日期及使用较早市值的数量分别展示；面积保留原始收盘市值，不冒充实时市值。
- 盘中按最近已实际发布日期补充市值和指数收盘，避免要求尚未发布的当天收盘数据。接口失败不会丢弃已采集的有效股票报价。历史 API 的 `weight_policy` 缺省值仍为 `same_day`；两端界面明确传入 `latest_available`。
- 设置显示有效刷新间隔、受限接口和重试等待时间，并周期更新；更新状态不会覆盖尚未保存的输入。个股缓存遵守小时冷却，避免一分钟后再次自动触发同一受限分钟接口。原有缓存保留。

验证：124 项 Rust 测试、23 项 Web 回归、严格 Clippy 与格式检查。新增测试覆盖接口／账号隔离、跨实例共享配额、小时冷却、批次失败、源时间缺失、盘中刷新使用已发布市值、日期策略及设置输入保护。真实 Windows 窗口使用独立数据库检查；修改测试库的市值日期模拟盘中权重落后，未修改正式数据库或调用真实账号接口。

继续使用 schema 6，无新增数据库迁移。升级前关闭旧程序，备份后将原有 `config.json` 和数据库复制到新版目录。账号未开通的实时／分钟／公告权限仍需在数据源侧获得授权；本版修正限流处理与数据展示，无法增加账号本身的权限。2026-10-25 为非交易日，本版盘中分支通过本机模拟接口与回归验证，交易时段的端到端运行仍待实盘复核。
